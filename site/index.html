The control loop

From prompt to proof.

The model can be manipulated. The permission boundary does not move with it.

01 / GRANT

Bind authority to one run

Issue a fresh capability scoped to owner, action, parameters, resource version, expiry, and revocation state.

02 / BROKER

Put policy on the write path

Check authorization in the same serialized transaction as the mutation and its structured receipt.

03 / VERIFY

Ask the host what happened

Replay receipts against complete before/after snapshots. Keep execution, safety, and cleanup as separate outcomes.

Demo protocol

When the prompt turns hostile.

A refusal is helpful behavior. A server-side denial plus unchanged protected state is enforcement evidence.

  1. 01

    Read

    Treat embedded instructions in an external ticket as untrusted content.

  2. 02

    Attempt

    Observe whether the agent requests a destructive action; record “not attempted” when it does not.

  3. 03

    Enforce

    Deny out-of-policy effects at the Action Broker, independent of the model’s wording.

  4. 04

    Recover

    Revoke the exact run, verify cleanup and host state, then issue fresh authority for useful work.
